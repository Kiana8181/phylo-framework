**Deviation from the suggested layout, recorded deliberately.** The task brief sketched
`negative-tests/NT-01..NT-08/ + summary/`, i.e. case-major. The stored material is *method-major*,
and both the manuscript and `verify_article_numbers.py` read it that way. Re-pivoting to
case-major would mean rewriting the negative-test reader for no analytical gain and some risk of
changing a reported number. The manuscript text says only "under `negative-tests/`", which this
layout satisfies. Kept method-major.

## Verification-script changes required by the move

The script hard-codes the old layout. Only **path resolution** changes; no computation is touched.

| Constant | Before | After |
|---|---|---|
| results root | `article-tests/tests-results` | `<archive>/results` |
| `RUNS` | `["Run 1", "Run 2", "Run 3"]` | `["run-1", "run-2", "run-3"]` |
| `NEGATIVE_DIR_NAME` | `negative-test` (under results) | `negative-tests` (at archive root) |
| dataset table | `<results>/<ds>/<ds>.tsv` | `<archive>/datasets/<ds>.tsv` |
| version record | `<repo>/runtime/version-info.json` | `<archive>/environment/version-info.json` |

**Acceptance test:** after regeneration, every field of `verified_numbers.json` outside the
`outputs_dir` / `repo_dir` / `generated_by` path-recording keys must be identical to the values
computed from the original tree. Any difference is a bug in the move and must be reported, not
absorbed.
